# RAG 模块

- 当前 `structure/feishu_doc` 提供树节点、添加/移除节点方法，以及异步 `await build_tree(list[DocxBlock]) -> BlockNode`：校验原始块关系并按标题层级构树，提取纯文本或图片 token 到 content，payload 保存代码语言或表格行列数、合并信息，构树完成后按文档顺序遍历全部图片节点，逐张串行调用 `image_parser.parse_image_block`（下载、私有桶上传、模型识图），等待完成再返回。识图模型取自 Nacos `rag_config.image_parser.vl_model_config`，必须是支持图片理解的模型；任一图片失败会使整篇文档失败。该目录不负责内容渲染。
- `loader/feishu_doc` 提供 `load_feishu_doc_structre(root, metadata=None) -> list[Document]`，按现成 children 结构提取页面、标题、图片、表格和代码文档；保留父正文、子引用及标题上下文，渲染 Markdown/HTML 并校验表格。输入不变，只使用现有依赖与本地计算；契约见下级指令。
- `splitter/feishu_doc` 提供 `split_feishu_doc(docs, *, chunk_size=1000, chunk_overlap=100)`：图片/代码不拆，表格第一行为表头并逐行切片，页面/章节按段落、句子与长度切分，保留目标 overlap 并保护完整占位符。长度固定按字符计量，完整标题也计入预算；切片 metadata 保留来源结构，新增 chunk_index/chunk_count，表格再加 table_row_index。输入不变，不读取飞书或调用模型。
- `embedding_model.py` 提供 `create_embedding_model(config=None)`：按 `RagEmbeddingModel` 构造 OpenAI 兼容的 `OpenAIEmbeddings`（默认 `text-embedding`、批量 10、1024 维），关闭上下文长度检查并指定 `encoding_format=float`；由 `store/feishu_doc` 的 `Milvus` 实例使用，索引写入与检索共用同一模型。
- `store/feishu_doc` 提供 Milvus Schema、稠密/稀疏索引参数、异步 `init_store()` 与 `get_store()`；按 Settings 和 Nacos `rag_config` 初始化数据库、集合与索引，已有集合仅在稠密索引类型或度量变化时重建该索引。`get_store()` 在锁保护下先初始化存储，再返回进程内缓存的 LangChain `Milvus` 向量库实例（collection `feishu_doc`，dense/sparse 双向量，BM25 内置函数）。新集合向量维度来自 `embedding_model.dimensions`，已有集合不迁移 Schema。具体契约见下级指令。
- `retriever/feishu_doc` 提供 `search(question, *, filter=None, config=None, threshold=0) -> list[SearchResult]`：把 `RetrieverConfig` 的 `fetch_k`、`k`、两路 `param` 与重排配置传给 `store.asimilarity_search_with_score`，重排由 Milvus 服务端执行（rrf、weighted、模型重排）。模型重排的 `params.model_name` 必须是 Milvus 端可解析的模型名，本地默认 `rerank` 会报 2400，需填 LiteLLM 别名。契约见 `retriever/feishu_doc/AGENTS.md`。
- 写入与删除由 `graphs/feishu_doc_index` 直接调用 `aupsert`/`adelete`，检索由 `retriever/feishu_doc` 调用同一 `Milvus` 实例；三者都未接入 `main_agent` 或服务启动流程，检索另由 `retrieve_agent` 图的 `before_agent` 中间件调用。切片函数不负责原始 Documents 或切片入库。图片处理的实现边界见 `structure/feishu_doc/AGENTS.md`。
- 不将此目录名称或类型定义视为已有完整 Agent 侧 RAG 能力；检索未注册为工具，也没有专门的检索自动化测试。
